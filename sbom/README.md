# Software Bill of Materials (SBOM)

This directory contains SBOM files generated by Syft for supply-chain transparency and security analysis.

## SBOM Files

- **sbom-cyclonedx.json**: CycloneDX format (OWASP standard)
- **sbom-spdx.json**: SPDX format (Linux Foundation standard)
- **sbom-table.txt**: Human-readable table format
- **sbom-syft.json**: Syft native detailed format

## What is an SBOM?

A Software Bill of Materials (SBOM) is a comprehensive inventory of all components (libraries, dependencies, packages) used in an application. It's similar to an ingredient list for software.

### Why SBOMs Matter

1. **Transparency**: Know exactly what's in your application
2. **Vulnerability Management**: Quickly identify affected components when CVEs are disclosed
3. **License Compliance**: Track open-source licenses
4. **Supply-Chain Security**: Detect malicious or unexpected dependencies
5. **Audit Trail**: Maintain a record of all components and versions

## Generating SBOMs

### Using the Script

```bash
cd /path/to/supply-chain-lab
./scripts/generate-sbom.sh
```

### Manual Generation

```bash
# CycloneDX format
syft dir:./app -o cyclonedx-json > sbom/sbom-cyclonedx.json

# SPDX format
syft dir:./app -o spdx-json > sbom/sbom-spdx.json

# Human-readable
syft dir:./app -o table
```

## Analyzing SBOMs

### Check for Suspicious Packages

```bash
# Search for @lab scope packages (malicious in this lab)
grep "@lab/" sbom/sbom-cyclonedx.json

# Check for unexpected sources
grep -i "localhost" sbom/sbom-cyclonedx.json
```

### Extract Package List

```bash
# List all packages
cat sbom/sbom-table.txt

# Count packages
cat sbom/sbom-table.txt | grep -v "^NAME" | wc -l
```

### Vulnerability Correlation

Use the SBOM with Grype to scan for known vulnerabilities:

```bash
grype sbom:sbom/sbom-cyclonedx.json
```

## SBOM Standards

### CycloneDX
- Maintained by OWASP
- Focus on application security use cases
- Supports vulnerability enrichment
- [Specification](https://cyclonedx.org/)

### SPDX
- Maintained by Linux Foundation
- Focus on license compliance
- ISO/IEC 5962:2021 standard
- [Specification](https://spdx.dev/)

## Integration with CI/CD

### GitHub Actions

```yaml
- name: Generate SBOM
  run: syft dir:./app -o cyclonedx-json > sbom.json

- name: Upload SBOM
  uses: actions/upload-artifact@v4
  with:
    name: sbom
    path: sbom.json
```

### Policy Enforcement

```bash
# Fail if suspicious packages are detected
if grep -q "@lab/" sbom/sbom-cyclonedx.json; then
    echo "Malicious package detected"
    exit 1
fi
```

## SBOM Attestation

For production systems, SBOMs should be:

1. **Signed**: Cryptographically signed to prove authenticity
2. **Timestamped**: Include generation timestamp
3. **Versioned**: Track changes across releases
4. **Accessible**: Published alongside artifacts

### Example: Sign SBOM with Cosign

```bash
# Generate key pair
cosign generate-key-pair

# Sign SBOM
cosign sign-blob --key cosign.key sbom-cyclonedx.json > sbom.sig

# Verify signature
cosign verify-blob --key cosign.pub --signature sbom.sig sbom-cyclonedx.json
```

## SBOM Distribution

### NTIA Minimum Elements

Per NTIA guidelines, SBOMs should include:

- Supplier name
- Component name
- Version of the component
- Other unique identifiers (CPE, PURL)
- Dependency relationships
- Author of SBOM data
- Timestamp

### Sharing SBOMs

```bash
# Publish to GitHub Release
gh release upload v1.0.0 sbom/sbom-cyclonedx.json

# Host on artifact registry
curl -X PUT "https://registry/sbom/app-v1.0.0.json" \
  --data-binary @sbom/sbom-cyclonedx.json
```

## Real-World Examples

### Log4Shell (CVE-2021-44228)

When Log4Shell was disclosed, organizations with SBOMs could:
1. Search SBOM for `log4j-core`
2. Identify affected applications instantly
3. Prioritize remediation efforts

```bash
grep -i "log4j" sbom/sbom-cyclonedx.json
```

### Dependency Confusion Attack

SBOMs help detect when private packages are replaced by public ones:

```bash
# Check for unexpected package sources
cat sbom/sbom-cyclonedx.json | jq '.components[] | select(.purl | contains("@company/"))'
```
